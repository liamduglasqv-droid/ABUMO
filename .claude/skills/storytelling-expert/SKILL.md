# Storytelling Expert

Turns ideas, drafts and data into stories that people remember and act on. Pick the right framework for the audience and goal, write the story in that structure, then tighten it with the craft rules.

## Workflow

1. **Read the brief.** Pin down four things: **audience** (who, what they know and care about, how skeptical they are), **objective** (what they should think, feel or *do* afterwards), **core message** (one sentence), and **format and length** (email, slide, speech, post, case study, and so on).
   If one of these is missing and it would change the result, ask up to 3 short questions. Otherwise, state your assumptions in one line and carry on.
2. **Pick one framework.** Use the table below. Blend frameworks only when the format calls for it. For example, open *In Medias Res* and then use *Minto* for the body of an executive email. Full templates are in `references/frameworks.md`.
3. **Draft the story.** Make the structure visible with short headings or labelled beats, unless the format is flowing prose such as a speech, a post or an email.
4. **Run a craft pass.** Apply the rules in `references/craft.md`. The key ones are: one hero, real stakes, concrete detail, a clear "but", numbers turned into meaning, and a call to action.
5. **Deliver it.** Give the finished text first. After it, add one line naming the framework and why you chose it (the user can switch frameworks). If the context is high-stakes, offer 1–2 alternative hooks or openings.

## Framework selection

| Situation | Framework | Spine |
|---|---|---|
| Marketing copy, website, proposal, value proposition | **StoryBrand** | Customer = hero with a problem → meets you, the guide → gets a plan → called to act → success / failure avoided |
| Vision, leadership, purpose, investor opener | **Golden Circle** | Why → How → What |
| Case study, project update, status report that should hold attention | **But / Therefore** (South Park) | Fact… BUT… THEREFORE… BUT… THEREFORE… |
| Origin story, change management, transformation narrative | **Pixar story spine** | Once upon a time… Every day… Until one day… Because of that (×n)… Until finally… Ever since then… |
| Complex B2B sale, "insight-led" pitch, reframing a client's thinking | **Challenger** | Warmer → Reframe → Rational drowning → Emotional impact → New way → Your solution |
| Executive briefing, recommendation, consulting deliverable, board paper | **Minto Pyramid / SCQA** | Situation → Complication → Question → Answer first, then 3 grouped supports |
| Personal story, overcoming adversity, customer transformation, keynote | **Hero's Journey** (simplified) | Ordinary world → Call → Struggle → Guide/insight → Transformation → Return with the lesson |
| Openings, crisis communication, social posts, anything that must hook fast | **In Medias Res** | Drop into the peak moment → rewind for context → resolve → lesson |
| Data-heavy update or analysis | **Data story** (see `references/frameworks.md` §9) | Insight headline → context/benchmark → the turning point in the data → implication → ask |

Tie-breakers:
- If the audience is senior and short on time, use **Minto**.
- If the goal is to change a belief, use **Challenger** or **But/Therefore**.
- If the goal is to rally emotion, use **Pixar** or the **Hero's Journey**.
- If the goal is to sell, use **StoryBrand**.

## Non-negotiables

- **Never invent facts, figures, quotes or client names.** If the story needs a detail you don't have, write a bracketed placeholder such as `[specific moment: e.g., the call when the CFO said…]` and point it out to the user.
- In a business story, **the customer or audience is the hero** and the writer or company is the guide.
- **One story, one message.** Cut anything that doesn't serve the core message.
- **Match the language and register** of the user. Framework names can stay in English.
